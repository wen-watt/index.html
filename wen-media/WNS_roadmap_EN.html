From SPL to RWA: how one standard taught Solana to keep its own promises

Five layers, five levels of abstraction, one idea running through all of them: an asset's rules should live inside the asset itself, not in agreements between platforms. SPL gave Solana a shared token language. Token-2022 taught that language to talk about hooks, metadata, and groups. WNS packaged those capabilities into a standard for NFTs. WEN proved it works with real money moving through it. And the RWA layer draws on the same foundation independently — not a direct continuation of the chain, but a parallel application of the same idea.

2020 - foundation

SPL Token

Solana's shared token standard. A simple balance model, with no built-in behavior logic.

2024 - extension

Token-2022

TLV-based extensions: Transfer Hook, Metadata Pointer, Group/Member, Confidential Transfers.

2024 - standardization

WNS

Bundles four extensions into one NFT interface: metadata, royalties, and groups inside a single mint.

2024 - practice

WEN

Weremeow's poem, minted as an NFT and fractionalized into a trillion tokens. The first working case for WNS.

parallel, not a successor

RWA Tokenization

Uses the same Token-2022 layer directly (Transfer Hook, Permanent Delegate) for KYC gating and compliance, bypassing the WNS NFT configuration entirely.

direct technical evolution shared foundation, independent use

Short notes

WEN is not RWA. WEN demonstrates the protocol's capabilities through a meme coin, not a compliance-grade financial instrument.

WNS is a configuration, not a platform. It's a set of Token-2022 settings tuned for NFT semantics, not a separate blockchain layer.

Direct impact of WEN/WNS falls on NFT royalty economics and Solana's creator economy.

Indirect impact is proof that embedding business logic inside a token works commercially, which motivates RWA builders working on the same Token-2022 base.
